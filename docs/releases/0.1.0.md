# Tondo 0.1.0

**Release date:** 2026-07-28

**Status:** released; Gate G5 passed

Tondo 0.1.0 is the first release of the complete Tondo 0.1 source-language
surface on the reference bytecode VM.

## Deliberate limits

This release claims conformance only for the target and capabilities above.
In particular:

- there is no native backend, stable native ABI, general FFI, dynamic linker,
  or serialized bytecode ABI;
- the VM executor is cooperative and single-threaded; Tondo tasks are
  concurrent but are not OS threads;
- `threads`, `filesystem`, `network`, `environment`, `clock`, `entropy`, and
  `dynamic-linking` are registered capability names but are not supported by
  this target;
- the process bridge never passes argv through an implicit shell;
- bytecode is verified and held in memory rather than distributed as a stable
  executable format;
- closed project builds do not resolve or download packages, scan directories,
  execute generators, or consult undeclared filesystem, network, environment,
  process, or clock state;
- the standard-library boundary currently exposes only the bootstrap
  `std.console` and `std.process` surfaces selected by capabilities;
- the `core` warning profile is implemented and conformance-pinned;
  `performance` and `docs-strict` remain optional profiles and are not exposed
  by this implementation; and
- no package manager, LSP, incremental compiler, native optimizer, or general
  standard-library distribution is claimed.

These are implementation and target limits, not alternative language
semantics. A missing target capability fails during project validation or
source checking rather than becoming a runtime stub.

## No conformance-only language mode

The compiler has one Tondo 0.1 frontend and one checked lowering path. Selecting
the `core` warning profile only adds warnings; it cannot suppress errors or
change runtime behavior. The `conformance` Cargo feature exposes the isolated
Appendix C document fixtures and a private collector observation adapter. It
does not add source syntax, bypass semantic checks, alter VM results, or make
those hooks reachable by a Tondo program.

The release suite invokes the public compiler and VM path for all ordinary
cases. Safe diagnostic fixes are replayed against the exact source snapshot,
and memory hooks are restricted to the four collector scenarios whose public
observations are schema-validated.
