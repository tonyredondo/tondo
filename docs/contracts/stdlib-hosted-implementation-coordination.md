# Hosted implementation coordination for `std.0.1A`

`STD-IMPL-002` coordinates `std.console`, `std.path`, `std.fs` and `std.process`.
Its reproducible register is `testing/stdlib-hosted-implementation-coordination.json`,
generated by `scripts/stdlib-hosted-implementation-coordination-generate.sh`.

Each owner requires indexed implementation and tests, verified component
`IMPL/HOST` evidence, and a nonempty public signature inventory without owner
or signature gaps. Capabilities match `testing/stdlib-hosted.json` exactly:

- `std.console` requires `console` and uses the `std.io` stream bridges.
- `std.path` is lexical, preserves native bytes, requires no capability and
  records `HOST not-applicable` with an explicit reason.
- `std.fs` requires `filesystem`; its hosted boundary includes handles,
  cleanup, limits and typed errors.
- `std.process` requires `process`; its boundary includes exact argv, pipes,
  separate/combined streams, cancellation and child reaping.

`closed-coordination` is derived from those four owners. Their 48 public
signatures retain their component evidence while the global API audit records
its own open gaps. Neither status substitutes for conformance observations,
complete public testing/metaprogramming integration, or native AOT execution.

```text
scripts/stdlib-hosted-implementation-coordination-check.sh
scripts/stdlib-hosted-implementation-coordination-test.sh
```

The checker validates register consistency, including an honest `open-gaps`
state. Tests accept the baseline before rejection probes, mutate generator
inputs to exercise empty/missing public surfaces, and verify that a pending
host stage reopens coordination. These checks do not publish Tondo or close S1A.
