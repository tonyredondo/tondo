# Standard library 0.1A evidence matrix

`STD-MATRIX-ALL-001` maintains `testing/stdlib-matrix.json`, generated by
`scripts/stdlib-matrix-generate.sh` and checked by
`scripts/stdlib-matrix-check.sh`. It indexes the 21 integration owners plus
`std.bytes`: currently 216 public signatures and 171 owner requirements.
Indexing a row does not prove its implementation or execution.

Each owner retains six stages: `SPEC -> IMPL/HOST -> MODEL/TEST/FUZZ -> PERF ->
CONF -> DOC`. Rows reference those records and their source contracts. A missing
required cell is a gap; an empty list cannot satisfy a stage. Non-applicable
host stages require an explicit reason, and every accepted cell needs nonempty
evidence references. The generator preserves missing public signatures and
owner routes in `IMPL/HOST`, `CONF` and `DOC` instead of overwriting them with
component status. Current public gaps include bytes, meta, reflection and
serialization. Their bounded kernels/models remain useful evidence.

## Component boundaries

- `std.core`, `std.text`, `std.collections`, `std.iter`, `std.math`,
  `std.format`, `std.io` and intrinsic `std.bytes` retain their compiler, VM
  and portable-kernel evidence.
- `std.console`, `std.fs` and `std.process` retain their capability boundaries;
  lexical `std.path` requires no filesystem capability. These hosted components
  do not establish native AOT execution.
- `std.time`, `std.env` and `std.async` retain their explicitly supplied
  provider/runtime boundaries. An imported module does not grant a capability.
- `std.serialization`, `std.json`, `std.messagepack` and `std.protobuf` retain their codec and event
  models. Built-in derive and Rust provider tests do not prove general Tondo
  metaprogramming providers or complete public protocol inventories.
- `std.reflect` catalog tests establish a metadata model. Runtime `typeInfo`
  integration and general public `std.meta` providers remain open.
- `std.testing` kernels and hosted helper tests do not close the public runner's
  remaining isolation, inputs, dependency and interruption contracts.

`testing/stdlib-owner-evidence.json` contains component evidence declarations.
Its MODEL/TEST/FUZZ references and historical performance records must be read
at their actual scope. `STD-A-FUZZ-001` is reopened: a fixed source admission
probe or a Rust model is not an input-dependent public runtime oracle. Logical
memory is not RSS, and a hosted campaign is not native AOT performance.

## Case plans and execution observations

`testing/stdlib-conformance.json` is a generated case plan with status
`planned`; its owner observations are `pending`. Manifest hashes and case
counts come from the current manifest. Generation reads no execution report
and cannot promote conformance. Meta and reflection cases identify their
component/model scope explicitly.

`testing/stdlib-conformance-coordination.json` maps every matrix row to its
owner's case plan and retains the current public gaps. Its promotion is pending.
A declared case is not proof of every requirement associated with its owner.
The generator never changes that distinction because a command string or
source path exists.

`scripts/stdlib-conformance-check.sh --plan` validates plan consistency only.
`scripts/stdlib-conformance.sh` executes the declared commands and examples,
compares runtime sidecars and writes a separate report under the selected
Cargo artifact directory (or `TONDO_STDLIB_EVIDENCE_DIR`). The default checker
requires that report, the current tree/revision/contract/manifest identities,
all declared owner commands and runtime sources, matching command logs, and
the full suite result and case observations. Successful execution still records
`public_row_coverage: unverified` and `promotion: pending`; complete public
coverage and the native adapter/lowering repairs are independent prerequisites.

```text
scripts/stdlib-matrix-test.sh
scripts/stdlib-conformance-test.sh --plan
scripts/stdlib-conformance-coordination-test.sh
```

These focused checks validate generated plans and reject unsupported promotion.
The default conformance test additionally requires a successful current
execution report before its negative evidence probes. It must not pass solely
because every probe was rejected against an already-invalid baseline.

The documentation coordinator retains owner contracts, examples and public
boundaries. Core/Hosted coordination, case-plan consistency and documentation
checks do not close S1A or publish Tondo. The live tracker records the remaining
implementation, observation and promotion work.
